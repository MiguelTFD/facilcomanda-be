Nuevos cambios - Invoice y cobro de ordenes

1. Nueva entidad: Invoice

Se agrego la entidad Invoice para guardar la informacion de cobro de una orden:
- Numero de factura: invoiceNumber
- Numero de orden: orderNumber
- Total de la orden: orderTotal
- Monto recibido del cliente: amountPaid
- Vuelto: changeAmount
- Metodo de pago: paymentMethod
- Fecha y hora de pago: paidAt
- Usuario/cajero que cobro: cashierUserId y cashierEmail
- Mesa asociada al momento del cobro: restaurantTableId y restaurantTableName
- Notas opcionales: notes

Importante:
El proyecto usa spring.jpa.hibernate.ddl-auto=validate, por eso PostgreSQL debe tener creada la tabla invoices antes de iniciar la aplicacion.

2. Nuevo estado de orden

Se agrego OrderStatus.PENDING_PAYMENT para representar las ordenes pendientes de pago.

Tambien se mantiene compatibilidad con ordenes DELIVERED en el listado/cobro, porque el proyecto ya tenia ese estado y puede estar siendo usado como orden lista para pagar.

3. Nuevos endpoints

PATCH /api/orders/{id}/status

Actualiza el estado de una orden.
No permite cambiar directamente a PAID. Para pagar una orden debe usarse el endpoint de cobro, asi se evita que una orden quede pagada sin factura.

Body:
{
  "status": "PENDING_PAYMENT"
}

Respuesta:
OrderResponse

GET /api/orders/pending-payment/occupied-tables

Lista ordenes pendientes de pago que tienen mesa asociada y cuya mesa esta OCCUPIED.
Incluye ordenes con estado PENDING_PAYMENT y DELIVERED.

Respuesta:
[
  {
    "id": 1,
    "restaurantTableId": 3,
    "tableName": "Mesa 3",
    "floorName": "Primer piso",
    "type": "DINE_IN",
    "status": "PENDING_PAYMENT",
    "total": 45.50,
    "orderDate": "2026-06-30T15:40:00",
    "items": []
  }
]

POST /api/invoices/orders/{orderId}/charge

Cobra una orden y crea su factura.
Reglas:
- La orden debe pertenecer a la organizacion autenticada.
- La orden no puede estar PAID ni CANCELLED.
- La orden debe estar PENDING_PAYMENT o DELIVERED.
- amountPaid debe ser mayor o igual al total de la orden.
- Si la orden tiene mesa asociada, la mesa pasa de OCCUPIED a AVAILABLE.
- La orden pasa a estado PAID.
- Solo se permite una factura por orden.

Body:
{
  "amountPaid": 50.00,
  "paymentMethod": "CASH",
  "notes": "Pago en efectivo"
}

Respuesta:
{
  "id": 1,
  "invoiceNumber": "INV-1-10-20260630154530",
  "orderId": 10,
  "orderNumber": 10,
  "restaurantTableId": 3,
  "restaurantTableName": "Mesa 3",
  "orderTotal": 45.50,
  "amountPaid": 50.00,
  "changeAmount": 4.50,
  "paymentMethod": "CASH",
  "paidAt": "2026-06-30T15:45:30",
  "cashierUserId": 2,
  "cashierEmail": "cajero@empresa.com",
  "notes": "Pago en efectivo"
}

GET /api/invoices

Lista las facturas de la organizacion autenticada, ordenadas por fecha de pago descendente.

GET /api/invoices/{id}

Obtiene una factura por id.

GET /api/invoices/orders/{orderId}

Obtiene la factura asociada a una orden.
